## Настраиваемые поля позволяют указать детали, необходимые вашему бизнесу

Добавьте свои собственные поля к клиентам, продуктам, счетам-фактурам, предложениям и входящим счетам-фактурам, чтобы каждая запись соответствовала вашему способу работы. Используйте настраиваемые поля для внутренних примечаний, ссылочных номеров, категорий, ссылок, вычислений, вложений и текста, сгенерированного AI, не меняя стандартный рабочий процесс.

<Callout kind="info">

Пользовательские поля зависят от компании. Создаваемое вами поле доступно только внутри учетной записи вашей компании и только для типа сущности, которому вы его назначили.

</Callout>

## Как работают настраиваемые поля

Пользовательские поля состоят из двух частей: **определения поля** и **значения поля**. Определение определяет, где появляется поле, какой тип входных данных оно принимает и можно ли его использовать в таблицах, формах или шаблонах PDF. Значением являются фактические данные, сохраненные в каждой записи.

Вы создаете поля для каждого типа сущности, а затем заполняете их при создании или редактировании записи. Например, вы можете добавить поле категории клиента для клиентов, поле SKU для продуктов или поле ссылки на проект для счетов.

### Типы сущностей

| Тип объекта | Используется для |
|---|---|
| `customer` | Сохраняйте дополнительные сведения о клиентах, такие как номер клиента, веб-сайт, дата регистрации или внутренние заметки. |
| `product` | Добавьте метаданные для конкретного продукта, такие как артикул, категория, вес, закупочная цена или сертификаты. |
| `invoice` | Собирайте детали счетов, такие как ссылки на проекты, накладные, статус утверждения или расчетные значения. |
| `quote` | Отслеживайте информацию, специфичную для предложения, например номера версий, примечания о сроке действия или этапы продаж. |
| `incoming_invoice` | Сохраняйте метаданные счетов поставщика, такие как ссылки на квитанции, поля утверждения или прикрепленные подтверждающие документы. |

<Callout kind="tip">

Сохраняйте имена полей, соответствующие типу записи. Поле типа `sku` имеет смысл для продуктов, а поле `project_reference` легче поддерживать в счетах-фактурах.

</Callout>

## Типы полей

Выберите тип поля в зависимости от типа данных, которые вы хотите, чтобы пользователи вводили или создавали.

| Тип поля | Описание |
|---|---|
| `text` | Однострочный ввод текста. |
| `multiline` | Многострочная текстовая область для более длинных заметок. |
| `email` | Ввод адреса электронной почты. |
| `url` | Ввод веб-сайта или ссылки. |
| `phone` | Ввод номера телефона. |
| `number` | Ввод целого числа. |
| `decimal` | Ввод десятичных чисел. |
| `amount` | Ввод суммы валюты. |
| `percent` | Числовой ввод отображается в процентах. |
| `date` | Выбор даты. |
| `datetime` | Выбор даты и времени. |
| `boolean` | Флажок с состоянием «да» или «нет». |
| `dropdown` | Поле с одним выбором и предопределенными вариантами. |
| `multiselect` | Поле с множественным выбором и предопределенными вариантами. |
| `autonumber` | Автоматически присваиваемый порядковый номер. |
| `lookup` | Ссылка на другую сущность. |
| `formula` | Вычисляемое поле на основе выражения. |
| `attachment` | Поле загрузки файла. |
| `ai` | Текстовое поле, созданное AI на основе сохраненного приглашения. |

## Конфигурация поля

Настройки полей управляют проверкой, видимостью и порядком. Настройте эти параметры при создании поля, а затем обновите их позже, если ваш рабочий процесс изменится.

<ParamField body="is_required" param-type="boolean" required="false" show-location="false">

Делает поле обязательным, когда пользователи заполняют форму записи.

</ParamField>

<ParamField body="is_unique" param-type="boolean" required="false" show-location="false">

Предотвращает дублирование значений для этого поля в записях одного и того же типа сущности.

</ParamField>

<ParamField body="show_in_table" param-type="boolean" required="false" show-location="false">

Показывает поле как столбец в представлениях списка для этого типа сущности.

</ParamField>

<ParamField body="show_in_form" param-type="boolean" required="false" show-location="false">

Показывает поле в формах создания и редактирования. Этот параметр включен по умолчанию.

</ParamField>

<ParamField body="available_in_pdf" param-type="boolean" required="false" show-location="false">

Делает поле доступным для шаблонов PDF. Этот параметр включен по умолчанию.

</ParamField>

<ParamField body="sort_order" param-type="integer" required="false" show-location="false">

Управляет порядком настраиваемых полей в выбранном типе сущности.

</ParamField>

## Создание настраиваемого поля

Создавайте поля из менеджера настраиваемых полей в настройках. Самый быстрый путь — сначала определить метку и тип, а затем включить только те параметры, которые вам нужны.

<Steps>
  <Step title="Открыть пользовательские поля" icon="settings">

  Войдите в NomadBill и откройте область настраиваемых полей в настройках.

  Выберите тип сущности, который вы хотите расширить, например клиенты, продукты, счета, предложения или входящие счета.

  </Step>
  <Step title="Создайте определение поля" icon="plus">

  Добавьте новое поле и введите **ярлык**, который будут узнавать члены вашей команды. NomadBill также создает **ключ** для поля из этой метки.

  Выберите **тип поля**, соответствующий данным, которые вы хотите собрать. Если вы выберете `dropdown` или `multiselect`, добавьте варианты, из которых пользователи смогут выбирать.

  </Step>
  <Step title="Настройка видимости и проверки" icon="edit">

  Включите необходимые параметры для этого поля, например «обязательный», «уникальный», «видимый в формах», «видимый в таблицах» или «доступный в шаблонах PDF».

  Если вы хотите, чтобы поле появилось раньше или позже других, измените порядок его сортировки перед сохранением.

  </Step>
  <Step title="Сохраните и протестируйте поле" icon="check-circle">

  Сохраните поле, затем откройте запись того же типа сущности и убедитесь, что ввод появляется там, где вы ожидаете.

  Успех выглядит как поле, отображаемое в форме или таблице в зависимости от включенных вами параметров.

  </Step>
</Steps>

<Callout kind="alert">

Вы не можете изменить тип поля после его создания. Если вам нужен другой тип, создайте новое поле и переместите рабочий процесс в это новое поле.

</Callout>

## Использование настраиваемых полей в записях

После создания поля NomadBill отображает его в записях этого типа сущности, если `show_in_form` включен. Пользователи могут вводить значения при создании новой записи или обновлять их позже в режиме редактирования.

Значения настраиваемых полей сохраняются для каждой записи. Поле уровня продукта применяется только к продуктам, а поле уровня счета-фактуры применяется только к счетам-фактурам. Если поле также отмечено `show_in_table`, это значение может отображаться в представлениях списка, что поможет вам быстрее сканировать и фильтровать записи.

Настраиваемые поля также поддерживают шаблоны редактирования страниц сведений. Это делает их полезными для информации, которую вы не всегда вводите заранее, например, для внутренних примечаний, дат последующих действий или вспомогательных вложений.

## Поля автонумерации

Используйте поля автоматической нумерации, если вам нужны последовательные идентификаторы, которые NomadBill назначает автоматически. Это хорошо работает для номеров клиентов, номеров продуктов, внутренних ссылок или других структурированных идентификаторов, которые не следует вводить вручную.

<Callout kind="info">

Поля автонумерации поддерживают три варианта настройки:

- **Префикс** добавляет текст перед числом, например `K-` или `P-`.
- **Заполнение** добавляет ведущие нули для достижения фиксированной ширины.
- **Старт** устанавливает первое число в последовательности.

Номер клиента может начинаться с `K-1000`, а номер продукта — с `P-00001`.

</Callout>

Каждый раз, когда создается новая запись, NomadBill присваивает этому полю следующий номер в последовательности. Это уменьшает дублирующую нумерацию и обеспечивает единообразие записей.

## Поля формул

Используйте поля формул, когда значение необходимо вычислить, а не вводить вручную. Поля формул полезны для итогов, наценок, процентных значений или вычислений для конкретных записей, которые зависят от других полей.

Выражение формулы может ссылаться на встроенные числовые значения и настраиваемые поля. Доступные переменные включают в себя:

- `subtotal`
- `vat_percentage`
- `total`
- `unit_price`
- `custom.KEY`

Например, вы можете использовать `custom.discount_rate * subtotal / 100` для расчета суммы скидки, если `discount_rate` хранится в другом настраиваемом поле. Значения формулы рассчитываются автоматически, когда NomadBill сохраняет значения настраиваемых полей.

<Callout kind="tip">

Клавиши полей формул должны быть простыми и предсказуемыми, чтобы выражения было легче читать. Такой ключ, как `discount_rate`, легче использовать в `custom.discount_rate`, чем длинный или непоследовательный стиль именования.

</Callout>

## Поля, сгенерированные AI

Используйте поля, сгенерированные AI, если вы хотите, чтобы NomadBill написал для вас текст на основе сохраненного приглашения. Это полезно для внутренних сводок, черновых описаний, последующих примечаний или стандартизированного текста, который должен быть создан на основе данных записи.

Прежде чем вы сможете использовать поле AI, создайте приглашение AI в диспетчере настраиваемых полей. Затем подключите это приглашение к полю при создании определения поля. В записях пользователи могут генерировать или повторно генерировать текст непосредственно из поля ввода.

NomadBill поддерживает следующие модели AI для подсказок:

- `google/gemini-3-flash-preview`
- `google/gemini-2.5-flash`
- `google/gemini-2.5-pro`
- `openai/gpt-5-mini`
- `openai/gpt-5`

<Callout kind="info">

Поля, сгенерированные AI, хранят текстовый вывод. Просмотрите созданный контент, прежде чем использовать его в документах для клиентов.

</Callout>

## Пользовательские поля в шаблонах PDF

Сделайте поле доступным в выводе PDF, включив `available_in_pdf` в определении поля. После этого вы можете разместить это поле в шаблонах документов и использовать настраиваемое значение при создании счетов, предложений или других PDF-файлов.

Если вы планируете включать настраиваемые поля в печатные документы, настройте их до завершения работы над шаблоном. Это сохранит структуру вашего шаблона стабильной и позволит избежать последующих доработок.

Прочтите [Шаблоны PDF](/ru/user-guide/pdf-templates), чтобы узнать о настройке шаблона и параметрах макета документа.
