## Os campos personalizados permitem recolher os dados de que a sua empresa precisa

Adicione os seus próprios campos a clientes, produtos, faturas, orçamentos e faturas recebidas para adaptar cada registo à sua forma de trabalhar. Utilize campos personalizados para notas internas, números de referência, categorias, ligações, cálculos, anexos e texto gerado por IA sem alterar o seu fluxo de trabalho habitual.

<Callout kind="info">

Os campos personalizados são específicos de cada empresa. Um campo que crie só está disponível na conta da sua empresa e para o tipo de entidade a que o atribuir.

</Callout>

## Como funcionam os campos personalizados

Os campos personalizados são compostos por duas partes: uma **definição do campo** e um **valor do campo**. A definição controla onde o campo aparece, o tipo de dados que aceita e se pode ser utilizado em tabelas, formulários ou modelos PDF. O valor corresponde aos dados efetivamente guardados em cada registo.

Crie campos por tipo de entidade e preencha-os ao criar ou editar um registo. Por exemplo, pode adicionar um campo de categoria aos clientes, um campo de SKU aos produtos ou um campo de referência de projeto às faturas.

### Tipos de entidade

| Tipo de entidade | Utilização |
|---|---|
| `customer` | Guardar dados adicionais sobre clientes, como o número de cliente, o site, a data de integração ou notas internas. |
| `product` | Adicionar metadados específicos de produtos, como SKU, categoria, peso, preço de compra ou certificações. |
| `invoice` | Recolher dados de faturas, como referências de projeto, notas de entrega, estado de aprovação ou valores calculados. |
| `quote` | Acompanhar informações específicas de orçamentos, como números de revisão, notas de validade ou fases de venda. |
| `incoming_invoice` | Guardar metadados de faturas de fornecedores, como referências de recibos, campos de aprovação ou documentos comprovativos anexos. |

<Callout kind="tip">

Utilize nomes de campos específicos para o tipo de registo. Um campo como `sku` faz sentido em produtos, enquanto `project_reference` é mais fácil de manter em faturas.

</Callout>

## Tipos de campo

Escolha um tipo de campo adequado aos dados que pretende que os utilizadores introduzam ou gerem.

| Tipo de campo | Descrição |
|---|---|
| `text` | Campo de texto numa única linha. |
| `multiline` | Área de texto com várias linhas para notas mais extensas. |
| `email` | Campo para endereço de e-mail. |
| `url` | Campo para site ou ligação. |
| `phone` | Campo para número de telefone. |
| `number` | Campo para número inteiro. |
| `decimal` | Campo para número decimal. |
| `amount` | Campo para montante monetário. |
| `percent` | Campo numérico apresentado como percentagem. |
| `date` | Seletor de data. |
| `datetime` | Seletor de data e hora. |
| `boolean` | Caixa de verificação com estado sim ou não. |
| `dropdown` | Campo de seleção única com opções predefinidas. |
| `multiselect` | Campo de seleção múltipla com opções predefinidas. |
| `autonumber` | Número sequencial atribuído automaticamente. |
| `lookup` | Ligação a outra entidade. |
| `formula` | Campo calculado com base numa expressão. |
| `attachment` | Campo para carregamento de ficheiros. |
| `ai` | Campo de texto gerado por IA com base num pedido guardado. |

## Configuração dos campos

As definições dos campos controlam a validação, a visibilidade e a ordenação. Configure estas opções ao criar um campo e atualize-as mais tarde se o seu fluxo de trabalho mudar.

<ParamField body="is_required" param-type="boolean" required="false" show-location="false">

Torna o campo obrigatório quando os utilizadores preenchem o formulário de um registo.

</ParamField>

<ParamField body="is_unique" param-type="boolean" required="false" show-location="false">

Impede valores duplicados nesse campo entre registos do mesmo tipo de entidade.

</ParamField>

<ParamField body="show_in_table" param-type="boolean" required="false" show-location="false">

Apresenta o campo como uma coluna nas vistas de lista desse tipo de entidade.

</ParamField>

<ParamField body="show_in_form" param-type="boolean" required="false" show-location="false">

Apresenta o campo nos formulários de criação e edição. Esta definição está ativada por predefinição.

</ParamField>

<ParamField body="available_in_pdf" param-type="boolean" required="false" show-location="false">

Disponibiliza o campo para modelos PDF. Esta definição está ativada por predefinição.

</ParamField>

<ParamField body="sort_order" param-type="integer" required="false" show-location="false">

Controla a ordem dos campos personalizados no tipo de entidade selecionado.

</ParamField>

## Criar um campo personalizado

Crie campos no gestor de campos personalizados das definições. A forma mais rápida é definir primeiro a etiqueta e o tipo e, depois, ativar apenas as opções necessárias.

<Steps>
  <Step title="Abra os Campos personalizados" icon="settings">

  Inicie sessão no NomadBill e abra a área de campos personalizados nas definições.

  Escolha o tipo de entidade que pretende alargar, como clientes, produtos, faturas, orçamentos ou faturas recebidas.

  </Step>
  <Step title="Crie a definição do campo" icon="plus">

  Adicione um novo campo e introduza uma **etiqueta** que as pessoas da sua equipa reconheçam. O NomadBill também cria uma **chave** para o campo a partir dessa etiqueta.

  Selecione o **tipo de campo** adequado aos dados que pretende recolher. Se escolher `dropdown` ou `multiselect`, adicione as opções que os utilizadores poderão selecionar.

  </Step>
  <Step title="Configure a visibilidade e a validação" icon="edit">

  Ative as opções de que precisa para esse campo, como obrigatório, único, visível em formulários, visível em tabelas ou disponível em modelos PDF.

  Se pretender que o campo apareça antes ou depois dos restantes, ajuste a ordem de apresentação antes de guardar.

  </Step>
  <Step title="Guarde e teste o campo" icon="check-circle">

  Guarde o campo, abra um registo do mesmo tipo de entidade e confirme se o campo aparece no local esperado.

  Se tudo tiver sido configurado corretamente, o campo aparecerá no formulário ou na vista de tabela de acordo com as opções ativadas.

  </Step>
</Steps>

<Callout kind="alert">

Não pode alterar o tipo de um campo depois de este ser criado. Se precisar de um tipo diferente, crie um novo campo e transfira o seu fluxo de trabalho para esse campo.

</Callout>

## Utilizar campos personalizados em registos

Depois de criar um campo, o NomadBill apresenta-o nos registos desse tipo de entidade quando `show_in_form` está ativado. Os utilizadores podem introduzir valores ao criar um novo registo ou atualizá-los posteriormente na vista de edição.

Os valores dos campos personalizados são guardados por registo. Um campo ao nível do produto aplica-se apenas a produtos e um campo ao nível da fatura aplica-se apenas a faturas. Se um campo também estiver marcado como `show_in_table`, o valor pode aparecer nas vistas de lista para facilitar a consulta e filtragem dos registos.

Os campos personalizados também podem ser editados nas páginas de detalhes. Isto torna-os úteis para informações que nem sempre são introduzidas logo de início, como notas internas, datas de seguimento ou anexos de apoio.

## Campos de numeração automática

Utilize campos de numeração automática quando precisar de identificadores sequenciais atribuídos automaticamente pelo NomadBill. São adequados para números de cliente, números de produto, referências internas ou outros identificadores estruturados que não devam ser introduzidos manualmente.

<Callout kind="info">

Os campos de numeração automática incluem três opções de configuração:

- **Prefixo** adiciona texto antes do número, como `K-` ou `P-`.
- **Preenchimento** adiciona zeros à esquerda até atingir um comprimento fixo.
- **Início** define o primeiro número da sequência.

Um número de cliente pode começar em `K-1000`, enquanto um número de produto pode utilizar `P-00001`.

</Callout>

Sempre que é criado um novo registo, o NomadBill atribui o número seguinte da sequência desse campo. Isto reduz a duplicação de números e mantém os registos consistentes.

## Campos de fórmula

Utilize campos de fórmula quando um valor deve ser calculado em vez de introduzido manualmente. Estes campos são úteis para totais, margens, valores percentuais ou cálculos específicos de um registo que dependam de outros campos.

Uma expressão de fórmula pode referenciar valores numéricos integrados e campos personalizados. As variáveis disponíveis incluem:

- `subtotal`
- `vat_percentage`
- `total`
- `unit_price`
- `custom.KEY`

Por exemplo, pode utilizar `custom.discount_rate * subtotal / 100` para calcular um montante de desconto quando `discount_rate` está guardado noutro campo personalizado. Os valores das fórmulas são calculados automaticamente quando o NomadBill guarda os valores dos campos personalizados.

<Callout kind="tip">

Mantenha as chaves dos campos de fórmula simples e previsíveis para facilitar a leitura das expressões. Uma chave como `discount_rate` é mais fácil de utilizar em `custom.discount_rate` do que um estilo de nomenclatura longo ou inconsistente.

</Callout>

## Campos gerados por IA

Utilize campos gerados por IA quando pretender que o NomadBill escreva texto por si com base num pedido guardado. São úteis para resumos internos, rascunhos de descrições, notas de seguimento ou texto normalizado gerado a partir dos dados dos registos.

Antes de utilizar um campo de IA, crie um pedido de IA no gestor de campos personalizados. Em seguida, associe esse pedido ao campo quando criar a definição. Nos registos, os utilizadores podem gerar ou voltar a gerar o texto diretamente no campo.

O NomadBill permite utilizar estes modelos de IA nos pedidos:

- `google/gemini-3-flash-preview`
- `google/gemini-2.5-flash`
- `google/gemini-2.5-pro`
- `openai/gpt-5-mini`
- `openai/gpt-5`

<Callout kind="info">

Os campos gerados por IA guardam texto. Reveja o conteúdo gerado antes de o utilizar em documentos destinados a clientes.

</Callout>

## Campos personalizados em modelos PDF

Disponibilize um campo em PDFs ativando `available_in_pdf` na definição do campo. Depois, pode inserir o campo nos modelos de documentos e utilizar o valor personalizado ao gerar faturas, orçamentos ou outros PDFs.

Se pretende incluir campos personalizados em documentos impressos, configure o campo antes de finalizar o modelo. Desta forma, mantém a estrutura do modelo estável e evita trabalho adicional mais tarde.

Leia [Modelos PDF](/pt/user-guide/pdf-templates) para saber mais sobre a configuração dos modelos e as opções de disposição dos documentos.
