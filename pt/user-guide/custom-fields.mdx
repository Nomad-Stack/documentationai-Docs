**Título:** Campos Personalizados

**Descrição:** Adicione metadados estruturados a clientes, produtos, faturas, orçamentos e contas de faturamento com 19 tipos de campos personalizados e regras de exibição flexíveis.

## Campos personalizados permitem capturar os detalhes que sua empresa precisa

Adicione seus próprios campos a clientes, produtos, faturas, orçamentos e faturas de entrada para que cada registro se adeque ao jeito como você trabalha. Use campos personalizados para notas internas, números de referência, categorias, links, cálculos, anexos e texto gerado por IA sem alterar seu fluxo de trabalho padrão.

<Callout kind="info">

Os campos personalizados são específicos da empresa. Um campo que você cria está disponível apenas dentro do seu conta corporativa e apenas para o tipo de entidade ao qual o atribuiu.

</Callout>

## Como os campos personalizados funcionam

Os campos personalizados são construídos de duas partes: uma **definição de campo** e um **valor de campo**. A definição controla onde o campo aparece, o tipo de entrada que aceita e se ele pode ser usado em tabelas, formulários ou modelos PDF. O valor é a data real salva em cada registro.

Você cria campos por tipo de entidade, então os preenche quando você cria ou edita um registro. Por exemplo, você poderia adicionar um campo de categoria de cliente para clientes, um campo SKU para produtos ou um campo de referência de projeto para faturas.

### Tipos de entidades

| Tipo de entidade | Usado para |
|---|---|
| `cliente` | Armazene detalhes adicionais sobre os clientes, como número do cliente, site, data de inscrição, ou notas internas. |
| `produto` | Adicione metadados específicos de produto, como SKU, categoria, peso, preço de compra ou certificações. |
| `fatura` | Capture detalhes da fatura, como referências de projeto, notas de entrega, status de aprovação ou valores calculados. |
| `orçamento` | Rastreie informações específicas do orçamento, como números de revisão, notas de validade, ou estágios de vendas. |
| `fatura de entrada` | Salve metadados da fatura fornecedora, como referências de recibo, campos de aprovação ou documentos anexos suportantes. |

<Callout kind="tip">

Manter nomes de campo específicos ao tipo de registro. Um campo como `sku` faz sentido em produtos, enquanto `project_reference` é mais fácil de manter nas faturas.

</Callout>

## Tipos de campos

Escolha um tipo de campo com base no tipo de dados que você deseja coletar ou gerar.

| Tipo de campo | Descrição |
|---|---|
| `texto` | Entrada de texto simples. |
| `multi-linha` | Área de texto multi-linha para notas mais longas. |
| `email` | Entrada de endereço de e-mail. |
| `url` | Entrada de site ou link. |
| `telefone` | Entrada de número de telefone. |
| `número` | Entrada numérica inteira. |
| `decimal` | Entrada numérica decimal. |
| `valor` | Entrada monetária com valor. |
| `percentual` | Entrada numérica mostrada como porcentagem. |
| `data` | Seletor de data. |
| `hora` | Seletor de hora e data. |
| `booleano` | Caixa de seleção com estado sim/não. |
| `caixa de seleção` | Campo único com escolhas predefinidas. |
| `seleção múltipla` | Campo múltipla com escolhas predefinidas. |
| `autonumero` | Número sequencial automaticamente atribuído. |
| `pesquisa` | Link para outra entidade. |
| `fórmula` | Campo calculado baseado em uma expressão. |
| `anexo` | Campo de upload de arquivo. |
| `IA` | Campo de texto gerado por IA com base em um prompt salvo. |

## Configuração dos campos

As configurações do campo controlam a validação, visibilidade e ordem. Configure essas opções quando você cria um campo, então atualize-as mais tarde se seu fluxo de trabalho muda.

<ParamField body="is_required" param-type="boolean" required="false" show-location="false">

Faz o campo obrigatório quando os usuários preenchem um formulário de registro.

</ParamField>

<ParamField body="is_unique" param-type="boolean" required="false" show-location="false">

Previne valores duplicados para esse campo em registros da mesma entidade tipo.

</ParamField>

<ParamField body="show_in_table" param-type="boolean" required="false" show-location="false">

Mostra o campo como uma coluna nas listas de visualização para essa entidade tipo.

</ParamField>

<ParamField body="show_in_form" param-type="boolean" required="false" show-location="false">

Mostra o campo no formulário de criação e edição. Esta configuração está habilitada por padrão.

</ParamField>

<ParamField body="available_in_pdf" param-type="boolean" required="false" show-location="false">

Faz o campo disponível para modelos PDF. Esta configuração está habilitada por padrão.

</ParamField>

<ParamField body="sort_order" param-type="integer" required="false" show-location="false">

Controla a ordem dos campos personalizados dentro do tipo de entidade selecionado.

</ParamField>

## Criando um campo personalizado

Crie campos no gerenciador de campos personalizados nas configurações. A maneira mais rápida é definir o rótulo e o tipo primeiro, então ativar apenas as opções que você precisa.

<Steps>
  <Step title="Abra Campos Personalizados" icon="settings">

  Entre em sua conta NomadBill e abra a área de campos personalizados nas suas configurações.

  Escolha o tipo de entidade ao qual deseja estender, como clientes, produtos, faturas, orçamentos ou faturas de entrada.

  </Step>
  <Step title="Crie a definição do campo" icon="plus">

  Adicione um novo campo e insira um **rótulo** que os membros da sua equipe reconhecerão. O NomadBill também cria uma **chave** para o campo com base neste rótulo.

  Se você escolher `caixa de seleção` ou `seleção múltipla`, adicione as opções que os usuários devem selecionar.

  </Step>
  <Step title="Configure a visibilidade e validação" icon="edit">

  Ative as opções que precisam para esse campo, como obrigatório, único, visível no formulário, visível na tabela ou disponível em modelos PDF.

  Se você quiser que o campo apareça antes ou depois de outros, ajuste seu ordem de classificação antes de salvar.

  </Step>
  <Step title="Salve e teste o campo" icon="check-circle">

  Salve o campo, então abra um registro do mesmo tipo de entidade e confirme que a entrada aparece onde você espera.

  O sucesso parece com o campo mostrando no formulário ou na visão da tabela com base nas opções que ativou.

  </Step>
</Steps>

<Callout kind="alert">

Você não pode alterar o tipo de um campo após sua criação. Se precisar de um tipo diferente, crie um novo campo e mova seu fluxo para esse novo campo.

</Callout>

## Usando campos personalizados em registros

Depois que você criar um campo, o NomadBill mostra-o nos registros dessa entidade tipo quando `show_in_form` está habilitado. Os usuários podem inserir valores enquanto criam um novo registro ou atualizá-los mais tarde do visualizador de edição.

Os valores dos campos personalizados são salvos por registro. Um campo de nível de produto aplica-se apenas aos produtos e um campo de nível de fatura aplica-se apenas às faturas. Se um campo também estiver marcado `show_in_table`, o valor pode aparecer nas listas para ajudar você a escanear e filtrar registros mais rapidamente.

Os campos personalizados também suportam padrões de edição de página detalhada. Isso isso, eles são úteis para informações que não sempre inserem inicialmente, como notas internas, datas de reunião ou anexos suportantes.

## Campos autonumero

Use campos autonumero quando você precisa de IDs sequenciais que o NomadBill atribui automaticamente. Isso funciona bem para números de cliente, números de produto, referências internas ou outros IDs estruturados que não devem ser inseridos manualmente.

<Callout kind="info">

Os campos autonumero suportam três opções de configuração:

- **Prefixo** adiciona texto antes do número, como `K-` ou `P-`.
- **Preenchimento** adiciona zeros à frente para alcançar uma largura fixa.
- **Início** define o primeiro número na sequência.

Um número de cliente pode começar em `K-1000`, enquanto um número de produto pode usar `P-00001`.

</Callout>

Cada vez que é criado um novo registro, o NomadBill atribui o próximo número na sequência para esse campo. Isso isso reduz a duplicação de numeração e mantém os registros consistentes.

## Campos de fórmula

Use campos de fórmula quando um valor deve ser calculado em vez de inserido manualmente. Campos de fórmula são úteis para totais, acréscimos, valores baseados em porcentagem ou cálculos específicos que dependem de outros campos.

Uma expressão de fórmula pode referenciar valores numéricos internos e campos personalizados. Variáveis disponíveis incluem:

- `subtotal`
- `vat_percentage`
- `total`
- `unit_price`
- `custom.KEY`

Por exemplo, você pode usar `custom.discount_rate * subtotal / 100` para calcular um valor de desconto quando `discount_rate` está armazenado em outro campo personalizado. Os valores de fórmula são calculados automaticamente quando o NomadBill salva os valores dos campos personalizados.

<Callout kind="tip">

Manter nomes de campo de fórmulas simples e previsíveis torna as expressões mais fáceis de ler. Um nome como `discount_rate` é mais fácil de usar em `custom.discount_rate` do que um estilo de nomeamento longo ou inconsistente.

</Callout>

## Campos gerados por IA

Use campos gerados por IA quando você deseja que o NomadBill escreva texto para você com base em um prompt salvo. Isso é útil para resumos internos, descrições de orçamentos, notas de reunião ou texto padrão que deve ser gerado a partir dos dados do registro.

Antes de poder usar um campo de IA, crie um prompt de IA no gerenciador de campos personalizados. Então conecte esse prompt ao campo quando você cria a definição do campo. No registros, os usuários podem gerar ou re-generar o texto diretamente do campo de entrada.

O NomadBill suporta esses modelos de IA para prompts:

- `google/gemini-3-flash-preview`
- `google/gemini-2.5-flash`
- `google/gemini-2.5-pro`
- `openai/gpt-5-mini`
- `openai/gpt-5`

<Callout kind="info">

Os campos gerados por IA armazenam o texto de saída. Revise o conteúdo gerado antes de usá-lo em documentos para clientes.

</Callout>

## Campos personalizados em modelos PDF

Faça um campo disponível no output PDF ativando `available_in_pdf` na definição do campo. Depois disso, você pode colocar o campo em suas plantas de documento e usar o valor customizado quando gerar faturas, orçamentos ou outros PDFs.

Se você planeja incluir campos personalizados em documentos impressos, configure o campo antes de finalizar sua planta de documento. Isso isso mantém a estrutura da sua planta de documento estável e evita reescrever depois.

Leia [Modelos PDF](/pt/user-guide/pdf-templates) para obter as opções de configuração e layout das plantas de documentos.
